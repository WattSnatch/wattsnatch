Vehicle Command Backend

Command backend controls where charge start/stop/amps/limit commands are sent; vehicle state source controls where battery/charging status data comes from - they can be set independently, or both switched to Bluetooth LE together. TeslaBleHttpProxy talks to the car directly over Bluetooth LE - no Tesla cloud round-trip - but only works while the car is within BLE range (a few metres), so it's meant for home charging, not away-from-home control.

Not practically usable on macOS. TeslaBleHttpProxy needs macOS's CoreBluetooth framework, which refuses unsigned/ad-hoc-signed code (a paid Apple Developer ID certificate is required) - it fails as a silent crash, not a permission prompt. Run it on a Linux machine instead (a Raspberry Pi near the car works well) and point the URL below at that machine - it doesn't need to be the same machine WattSnatch runs on.

Set both to Bluetooth LE for a fully cloud-free setup - no Fleet Telemetry, no Fleet API, no Tesla token needed. In BLE state mode the car's presence is detected over Bluetooth (in range = at home), so it replaces GPS geofencing too. Reading state over Bluetooth takes a few seconds and is polled about every 30s, so it reacts a little slower than Fleet Telemetry's live push.

Checks that the proxy is reachable at that URL. It does not send any command to your car. Only Bluetooth range and the paired key determine whether commands actually reach the vehicle.

Two independent, optional integrations over MQTT: turn on either, both, or neither. Publishing sends WattSnatch's own sensors to Home Assistant. Not configured

The only thing needed on the HA side is its own Settings → Devices & Services → MQTT integration, already connected to this same broker.

Bring your own inverter data
Not configured

For any inverter WattSnatch doesn't talk to directly: map two of your existing sensors (solar production, and either grid or house consumption) as plain-number MQTT topics, and WattSnatch derives the rest itself. If that data already shows up as sensors in Home Assistant, the easiest way onto MQTT is HA's built-in MQTT Statestream integration. Add this to configuration.yaml: 

mqtt_statestream:
  base_topic: homeassistant/statestream
  include:
    entities:
      - sensor.your_solar_power
      - sensor.your_grid_power

After restarting Home Assistant, those sensors publish live to e.g. homeassistant/statestream/sensor/your_solar_power/state, use that as a topic below. Values like "1234 W" are fine too, the unit suffix is stripped automatically.

Set this to MQTT to make WattSnatch use the settings below as its live inverter data, instead of a direct gateway connection.

Backup & Restore

Downloads a zip of your database and local keys/certs to wherever your browser saves downloads (you'll get the normal "Save As" prompt if your browser is set to ask). Do this before every update - a bad update is a 10-second recovery if you have a recent backup, and a bigger problem if you don't.

The backup does not include credentials stored in your OS's secure keychain (myenergi/MELCloud/iCloud) - those stay on this machine and aren't affected by restoring a backup here. Restoring on a different machine will need those re-entered.

Download Backup

An encrypted backup is safer to store off this machine (cloud sync, USB drive, email) since it includes your Tesla command key. There is no password recovery for an encrypted backup - if you lose the password, the backup is unreadable.

To restore a backup or roll back after an update, run npm run restore <path-to-backup.zip> from the WattSnatch folder (add .enc to the filename and it'll prompt for the password) - see the Updating & rollback docs.

Automatic daily backups

Runs itself once a day - no button-pressing or cron jobs needed. Kept for a week, then thinned to one per week for about three months, then deleted. Stored in ~/.solarcharge/backups/auto/; restore any of them the same way as a downloaded one.
